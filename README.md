# K4RC Training Plan

ตารางซ้อมสำหรับนักกีฬา K4RC ติดตั้งเป็นแอปบนไอโฟน/แอนดรอยด์ได้ (PWA)

- `/` นักกีฬาล็อกอินด้วยอีเมล + รหัสผ่านที่โค้ชสร้างให้ แล้วเห็นแผนของตัวเอง (ดูตัวอย่างหน้าตา: `/?demo=1`)
- `/admin.html` หน้าโค้ช: สร้างบัญชี, นำเข้าแผน, แก้รายสัปดาห์, ส่งแผนให้นักกีฬาคนอื่น, สำรอง/กู้คืนข้อมูล, ส่งอีเมล

## นักกีฬานอก: สมัครเองและรับตารางซ้อมอัตโนมัติ (v94)

**ลำดับหน้า (v95):** Welcome (splash) → **หน้าเข้าสู่ระบบ** (`login.css`, รูปนักวิ่งเต็มจอ + ฟอร์มอีเมล/รหัสผ่าน; รวมหน้า Get Started เดิมเข้ามาแล้ว) → ปุ่ม **สร้างบัญชี** → หน้าสมัครนักกีฬานอก → แอป
- เข้าสู่ระบบด้วยอีเมล + รหัสผ่านเหมือนเดิม (`POST /api/login`) · **สร้างบัญชี** → หน้าสมัคร (อีเมล, รหัสผ่านอย่างน้อย 8 ตัว, ชื่อเล่น, PB 5K) · logout กลับมาที่หน้าเข้าสู่ระบบ · หน้าจอปรับตามขนาด: มือถือ/ไอแพดตั้ง = แผ่นฟอร์มล่าง, จอกว้างตั้งแต่ 900px = ฟอร์มซ้าย รูปขวา
- เป้าหมายตายตัว: **Buriram Marathon 2027 · Half-Marathon 21.1 กม. · 23 ม.ค. 2027** (ค่าอยู่ใน `EXT_GOAL` ที่ `netlify/lib/external.mts`)

**ตอนสมัคร (`POST /api/register`) ระบบทำให้ครบในครั้งเดียว** (ตรรกะอยู่ใน `netlify/lib/external.mts`)
1. PB 5K → VDOT → เพซซ้อมทั้ง 7 ค่า (ใช้สูตรเดียวกับตัวช่วยคำนวณของโค้ช) + เวลาและเพซฮาล์ฟคาดการณ์ → บันทึกเป็นเพซของนักกีฬา และใส่ PR 5K / เป้าหมายเวลาในโปรไฟล์
2. จับคู่ตารางฮาล์ฟ 6 แผน (`half-plans-data.mts`) ที่เวลาเป้าหมายใกล้เวลาคาดการณ์ที่สุด (เท่ากันเลือกแผนที่ช้ากว่า)
3. วางตารางย้อนจากวันแข่ง: วันสุดท้ายของตาราง (วันแข่ง) = 23 ม.ค. 2027, นับถอยหลังทีละ 7 วัน ได้ 15 สัปดาห์ ตัดวันที่ผ่านไปแล้วทิ้ง (สมัครช้า = ได้เฉพาะส่วนที่เหลือ) งานผ่านไปแล้วปิดรับสมัคร
4. เพซในแผนไม่ใช้ค่าจาก PDF: Easy → LT1, Tempo → LT2, Steady → Marathon, 3K → VO2Max, 5K → 5K, 800 ม./1 ไมล์ → R, วอร์ม/คูล/พักระหว่างเซ็ต → Recovery (แก้ตารางจับคู่ได้ที่ `toWorkout`)
5. ตัด **Park Run** ออก ("วิ่งเบา หรือ Parkrun" เก็บส่วนวิ่งเบาไว้) · **Interval** ทุกเซสชันได้วอร์มอัพ 15 + คูลดาวน์ 15 นาทีเสมอ (`WARM_COOL_MIN`)
6. ปรับตารางสำเร็จรูปทุกแผนที่ `customize()` (`external.mts`): **วันที่ว่าง** (เช่น วัน Parkrun ที่ถูกตัดออก) → **Easy 40 นาที** · **Easy ล้วน 20 นาที → 40 นาที** (ไม่แตะส่วน Easy ในวัน Easy + Tempo) · **วันพัก (rest) คือพักตามปกติ** · ใช้กับคนที่สมัครหลังอัปเดต (ตารางของคนที่สมัครไปแล้วไม่เปลี่ยน)

นักกีฬานอกเป็นนักกีฬาปกติในระบบ (มีฟิลด์ `ext` เพิ่ม) จึงใช้หน้าแผน เพซ ติ๊กทำแล้ว ฟีดทีมเดียวกันทุกอย่าง · โค้ชดูได้ที่แท็บ **นักกีฬานอก** (หน้าโค้ช) และมีป้ายระบุในแท็บ ภาพรวม/นักกีฬา · backup/restore เก็บ `ext` ด้วย
- ปิดรับสมัครชั่วคราว: ตั้ง `EXTERNAL_SIGNUP=off` ใน Netlify · จำกัดสมัครต่อ IP: 8 ครั้ง/15 นาที
- สร้างข้อมูลแผนใหม่จาก PDF: `python3 tools/extract_half_plans.py <โฟลเดอร์ PDF> netlify/lib/half-plans-data.mts` (ตารางต้นฉบับมี 4 เซลล์ที่ PDF ตัดข้อความข้ามหน้า สคริปต์เติมให้ใน `OVERRIDES`)

## ธีม iOS 27 "กระจกสว่าง" (Liquid Glass) — ใช้ทั้งหน้านักกีฬาและหน้าโค้ช
- ไฟล์สไตล์ธีมคือ `public/ios27.css` (โหลดหลังสุด) ที่เดียว: ตัวแปรสี, Dock, หน้าต่างกระจก, ปุ่มความรู้สึก, หน้าโค้ช (มือถือ + คอม)
  ส่วน `kotcha.css` / `athlete.css` เหลือเฉพาะโครงเลย์เอาต์ (ล้างสีแบบตายตัวของธีมมืดออกหมดแล้ว) สีทั้งหมดอ่านจากตัวแปรใน `ios27.css`
- **Dock ล่าง:** ไอคอนล้วน กระจกใส กดแตะหรือรูดนิ้วข้ามแท็บได้ (กดค้างแล้วแท่งไฮไลต์ขยาย) ตำแหน่งอิงจาก safe area ของไอโฟน (`bottom = max(12px, safe-area − 12px)`)
- **หลังซ้อม:** ถามข้อเดียว "วันนี้ซ้อมรู้สึกอย่างไร" 5 ระดับ (สบาย · พอดี · เริ่มหนัก · หนัก · สุดแรง) เก็บเป็น RPE 2/4/6/8/10 ส่วนช่อง "รู้สึกอย่างไร" (1–5) เดิมเอาออกจากฟอร์ม
  ข้อมูลเก่ายังแสดงตามเดิม (ค่า RPE คี่ เช่น 7 จะไฮไลต์ระดับที่ใกล้สุด) หมายเหตุ: ฟีเจอร์ "รู้สึกแย่" ในภาพรวมโค้ชจะไม่เกิดจากฟอร์มใหม่ แต่ "เหนื่อยมาก (RPE 9+)" และ "มีอาการเจ็บ" ยังทำงาน
- **หน้าโค้ชบนคอม** (กว้างตั้งแต่ 900px): แถบเมนูด้านซ้าย ภาพรวมเป็นตาราง ปฏิทินสัปดาห์ 7 คอลัมน์ หน้าต่างแก้เวิร์คเอาต์ ส่วนบนมือถือใช้ Dock เดียวกับฝั่งนักกีฬา
- **ไอคอนแอป:** แบบ D "Smoked Glass" (`public/icons/*-v3.png` และไฟล์ต้นฉบับ 1024px อยู่ที่ `assets/icon-1024-v3.png`) ถ้าเปลี่ยนไอคอน ให้เปลี่ยนชื่อไฟล์เป็น `-v4` เพื่อกันแคชของมือถือ
- **ฟอนต์:** เก็บในโฟลเดอร์ `public/fonts/` เองทั้งหมด (Plus Jakarta Sans สำหรับตัวเลข/อังกฤษ + Prompt สำหรับไทย) ไม่เรียก Google Fonts แล้ว เปิดแอปเร็วขึ้นและใช้ออฟไลน์ได้
  Roboto Mono กับ Orbitron โหลดเฉพาะตอนวาดภาพแชร์
- **ความเร็ว:** เบลอ (`backdrop-filter`) เหลือเฉพาะ Dock / หน้าต่างลอย / ข้อความแจ้งเตือน / แถบปุ่มบันทึกของโค้ช (การ์ดทั่วไปไม่เบลอเพื่อไม่ให้มือถือรุ่นเก่ากระตุก)
  `sw.js` ใช้ไฟล์ในแคชทันทีแล้วอัปเดตเบื้องหลัง หน้า HTML ถ้าเน็ตช้าเกิน 4 วินาทีใช้ของที่แคชไว้ **ทุกครั้งที่ปล่อยเวอร์ชันใหม่ให้เปลี่ยนเลข `VER` ใน `sw.js`**
- **ความปลอดภัย:** ใส่หัว CSP/nosniff/frame ใน `netlify.toml` และรหัสโค้ชผิด 8 ครั้งจะถูกล็อก 15 นาที (ต่อ IP) เทียบรหัสแบบเวลาคงที่

## หน้านักกีฬา (ฟีเจอร์หลัก)
- **แผน:** ใช้งานเหมือนเดิม: กล่องสรุปสัปดาห์ (กม. ที่ทำแล้วเทียบแผน, แถบเวิร์คเอาต์รายครั้ง, เวลา, โหลด) วงกลม 7 วันกดเลือกวัน แล้วการ์ดของวันนั้นแสดงรายละเอียดในหน้าเลย (กราฟ ขั้นตอน เพซ ท่าสเตรงท์) กด "ทำเสร็จแล้ว" แล้วให้ความรู้สึกหลังซ้อม
- **ปฏิทิน:** รายเดือน พื้นเขียวคือทำครบ พื้นแดงคือมีค้าง กดวันเพื่อไปที่วันนั้น
- **สถิติ:** ระยะทางรายสัปดาห์ (แผนเทียบที่ทำแล้ว) และกราฟ Fitness / Fatigue / Form คำนวณจากเวลา x RPE ที่นักกีฬาให้หลังซ้อม (เป็นค่าประมาณ ไม่ใช่ TSS ของ TrainingPeak)
- **เพซ:** แท่งยาวตามความเร็ว **โปรไฟล์:** ผ้าเบอร์นับถอยหลังวันแข่ง ความสำเร็จ (กม. สะสม จำนวนครั้ง สัปดาห์ที่ทำครบ)

## ฟีเจอร์ใหม่ (รอบนี้)
- **Welcome + ไอคอนพื้นขาว (v93):** พื้นหน้า Welcome (`#splash` ใน `night.css`) เปลี่ยนจากแดง #ee3b2b เป็นขาว โลโก้ `k4rc-splash-logo.png` กับแถบโหลดยังสี #2b2c30 ไอคอนแอปทุกขนาดทำใหม่พื้นขาว (โลโก้เดิม) เป็น `-v5` (`apple-touch-icon`, `favicon-32`, `icon-192`, `icon-512`, `maskable-512`) แทน `-v4` สี `theme-color` ระหว่าง splash และ `background_color`/`theme_color` ใน `manifest.webmanifest` เป็นขาว
  - iOS/Android จำไอคอนตามตอนติดตั้ง: นักกีฬาที่ติดตั้งไว้แล้วต้องลบไอคอนบนหน้าจอโฮมแล้ว "ติดตั้งเป็นแอป" ใหม่ถึงจะเห็นไอคอนพื้นขาว (หน้า Welcome ใหม่เห็นทันทีหลังอัปเดต)
- **หน้าตาใหม่ (v92):** ทำเป็นไฟล์แยก ถอดไฟล์ใดไฟล์หนึ่งออก (และลบบรรทัด `<link>`/`<script>` ใน `index.html` + `SHELL` ของ `sw.js`) เพื่อย้อนส่วนนั้นได้
  - `theme-mono.css` — ธีมโมโน (พื้นเทากลาง การ์ดทึบ ปุ่มหลักขาว/ดำ ไม่มีสีแดงนำ) ทับตัวแปรสีของ `night.css` โลโก้และ splash ยังแดง สีสถานะ/โซนคงเดิม
  - `layout-v2.css` — Dock 2+1 (แท่ง "หน้าแรก/สถิติ" มีชื่อใต้ไอคอน + ปุ่มกลมโปรไฟล์แยก, ลากนิ้วได้ในแท่ง) · แถบบนติดค้าง (ปุ่มแผนเฉพาะหน้าแรก | โลโก้กลาง | ข้อความจากโค้ชเฉพาะหน้าแรก) · กราฟระยะทางรายสัปดาห์แบบแท่งแคปซูล แตะดูตัวเลข · จังหวะระยะห่างเดียวกันทุกหน้า (บล็อกหลัก 14px, แถบบนสูง 44px, ท้ายหน้า 24px เหนือ Dock)
  - `motion.css` + `motion.js` — ลูกเล่นขยับตอนเข้าหน้า (การ์ดไล่ขึ้น, ตัวเลขนับขึ้น, วงกลม/แท่งโต, แสงวิ่งผ่านโลโก้) เล่นครั้งเดียวต่อการเข้าหน้า ไม่ขยับเมื่อเครื่องตั้ง "ลดการเคลื่อนไหว"
  - หน้าแผนเข้าทางปุ่มมุมซ้ายบนของหน้าแรก (ไม่อยู่ใน Dock แล้ว) หน้าสถิติ/แผนไม่มีหัวข้อตัวใหญ่ คำทักทายหน้าแรกถูกถอด
- **แก้บั๊ก (v91):** (1) รายการแคชออฟไลน์ใน `sw.js` ขาดฟอนต์ 4 ตัว (`k4-jakarta-var`, `k4-noto-sans-thai`, `orbitron-latin-900`, `roboto-mono-latin`) เปิดแอปครั้งแรกแล้วตัดเน็ตจะได้ฟอนต์ผิด เพิ่มแล้ว + เทสต์ตรวจว่าไฟล์ที่ HTML/CSS อ้างถึงอยู่ใน SHELL ครบ (2) ส่ง body JSON เป็น `null` ไป `/api/*` แล้วตอบ 502/503 ทั้งที่ควรเป็น 4xx เพราะ `req.json().catch(() => ({}))` จับได้แค่ JSON พัง ตอนนี้ใช้ `readJson()` กลางที่ได้ object เสมอ + เทสต์
- **ถอดระบบถาม AI (v90):** ลบแท็บถาม AI, `/api/ask`, `netlify/lib/ai.mts`, `ask.css` และเทสต์ออกทั้งหมด Dock กลับเป็น 4 ปุ่ม env `GEMINI_API_KEY`/`GEMINI_MODEL`/`AI_DAILY_LIMIT`/`AI_DISABLED` ไม่ใช้แล้ว ลบทิ้งใน Netlify ได้ (ตัวนับเก่า `ai:<id>` ที่ค้างในฐานข้อมูลไม่มีผล)
- **ข้ามวันนี้ (v90):** การ์ดเวิร์คเอาต์มีปุ่ม "ข้ามวันนี้" (ซ้าย เล็ก) คู่กับ "ทำเสร็จแล้ว" (ขวา) เก็บที่ key `skip:<id>` (map workoutId → 1) ผ่าน `POST /api/done` body `{ workoutId, skip: true|false }` (ไม่มีคีย์ `done`) และส่งกลับใน `GET /api/plan` เป็น `skip`
  - กติกา: ทำเสร็จแล้ว = เลิกข้ามเอง, เวิร์คเอาต์ที่ทำแล้วตั้งข้ามไม่ได้, วางแผนใหม่ทั้งชุด/ลบนักกีฬา = ล้าง skip, ไม่ขึ้นฟีดทีม
  - สถิติ: **ข้ามไม่ช่วยและไม่ทำให้เสียสถิติ** (เปอร์เซ็นต์/สัปดาห์ติดต่อกัน/เหรียญนับเหมือนไม่ได้ทำ) แค่แสดงเป็นสีเทาแทนสีแดง "ค้าง" ในแถบสัปดาห์ ปฏิทินเดือน และชิปวันหน้าแผน
  - ออฟไลน์: ใช้คิว `qPush` เดียวกับปุ่มทำเสร็จ (รายการ `{workoutId, skip}` แยกจาก `{workoutId, done}` ตอน `qApply`)
  - ยังไม่ได้ทำ: ให้โค้ชเห็นว่านักกีฬาข้ามเวิร์คเอาต์ไหน (ข้อมูลอยู่ใน `skip:<id>` แล้ว เหลือแค่แสดงในแดชบอร์ดโค้ช)
- **ปรับหน้าตา (v87):** `refine.css` + `refine2.css` — จำกัดสีแดง, แถบโซนความเหนื่อยบาง + คำอธิบาย, ตัวเลขหลักฟอนต์เอียงหนา (Orbitron), เมนูล่างมีเงาไล่เฉด, กราฟระยะทางรายสัปดาห์เต็มความกว้างพร้อมตัวเลข, ฟีดทีมกระชับ, การ์ดข้อความโค้ช (อวตาร K4), หน้าสรุปหลังซ้อมจัดใหม่, มุมโค้ง 3 ขนาด (28/18/เม็ดยา)

## รันทดสอบในเครื่องคอม (ก่อนขึ้น Netlify)
ต้องมี Node.js 18 ขึ้นไป (ดาวน์โหลดที่ nodejs.org)
1. เปิด Terminal ในโฟลเดอร์โปรเจกต์ แล้วรัน `npm install` (ครั้งแรกครั้งเดียว)
2. คัดลอก `.env.example` เป็น `.env` แล้วแก้ `ADMIN_PASSWORD=` เป็นรหัสโค้ชที่ต้องการ (ไม่ทำก็ได้ ระบบใช้รหัส `coach` ให้ชั่วคราว)
3. `npm run dev` แล้วเปิด
   - http://localhost:8888/?demo=1 ดูหน้านักกีฬาด้วยข้อมูลตัวอย่าง (ไม่ต้องล็อกอิน)
   - http://localhost:8888/admin.html หน้าโค้ช: สร้างบัญชีนักกีฬา ตั้งเพซ ลงแผน
   - http://localhost:8888/ หน้านักกีฬาจริง ล็อกอินด้วยบัญชีที่เพิ่งสร้าง (เปิดอีกหน้าต่างแบบไม่ระบุตัวตนเพื่อทดสอบคู่กับหน้าโค้ช)
4. ข้อมูลที่ทดลองเก็บในโฟลเดอร์ `.devdata` ลบทิ้งเมื่ออยากเริ่มใหม่ ข้อมูลนี้แยกจากบน Netlify ไม่ปนกัน
5. อีเมลอัตโนมัติ (Resend) ไม่ทำงานในโหมดนี้ถ้าไม่ได้ใส่ `RESEND_API_KEY` และ `EMAIL_FROM` ใน `.env`

## ตัวสร้างเวิร์คเอาต์ (หน้าโค้ช → แผนซ้อม → เวิร์คเอาต์ประเภท "วิ่ง")
- กดปุ่มแบบสำเร็จรูป (วิ่งเบา, เทมโป, Sub-threshold, อินเทอร์วัล 800 ม., VO2Max) แล้วแก้ตัวเลข หรือเพิ่มขั้นเองด้วย "+ วอร์มอัพ / + อินเทอร์วัล / + คูลดาวน์"
- แต่ละขั้นเลือกปริมาณเป็น กม. / ม. / นาที / วินาที และเลือกเพซจาก Recovery, LT1 (Easy), LT2 (Threshold), Marathon, 5K, VO2Max, R ของนักกีฬาคนนั้น (หรือ "กำหนดเอง" เช่น 4:20)
- ระบบคำนวณเวลาและระยะรวมให้ และวาดกราฟแท่ง (กว้าง = เวลา, สูง = ความเร็ว) ให้ดูทันทีขณะกรอก
- อินเทอร์วัลพักระหว่างรอบเท่านั้น (ไม่มีพักหลังรอบสุดท้าย) ถ้าต้องการพักหลังรอบสุดท้ายให้เพิ่มเป็นขั้น "วิ่งต่อเนื่อง" เบาๆ ต่อท้าย
- เวลาและระยะคำนวณใหม่อัตโนมัติเมื่อบันทึกสัปดาห์ เมื่อแก้เพซของนักกีฬา และเมื่อส่งแผนให้คนอื่น (ใช้เพซของคนที่รับ)
- ถ้าเพซที่ใช้ยังไม่ได้ตั้ง จะขึ้นเตือนและยังไม่คำนวณ ไปตั้งที่แท็บ "นักกีฬา" → "เพซของ …"

## ติดตั้งเป็นแอป
- **iPhone / iPad**: เปิดเว็บใน Safari → ปุ่มแชร์ → "เพิ่มลงในหน้าจอโฮม" (ในแอปมีปุ่ม "ติดตั้งเป็นแอป" บอกวิธีให้ด้วย)
- **Android**: เปิดใน Chrome → กดปุ่ม "ติดตั้งเป็นแอป" ในหน้าเว็บ หรือเมนู ⋮ → "ติดตั้งแอป"
- ไอคอนและชื่อแอป (K4RC Training Plan) ตั้งไว้ที่ `public/manifest.webmanifest` และโฟลเดอร์ `public/icons/`
- เปิดตอนออฟไลน์ได้ จะเห็นแผนที่โหลดไว้ล่าสุด (อ่านอย่างเดียว ติ๊กทำแล้วต้องมีเน็ต)
- ถ้าเปลี่ยนไฟล์ในแอป แล้วอยากให้เครื่องที่ติดตั้งไว้ดึงเวอร์ชันใหม่ ให้แก้เลข `VER` ใน `public/sw.js`

## ส่งแผนให้นักกีฬาคนอื่น (หน้าโค้ช → แท็บ "แผนซ้อม")
เลือกนักกีฬาต้นทาง → ส่วน "ส่งแผนนี้ให้นักกีฬาคนอื่น" → ติ๊กชื่อคนที่จะส่งให้
- **ทั้งแผน**: คัดลอกทุกสัปดาห์ ใส่วันที่ "เริ่มสัปดาห์แรกวันที่" ถ้าอยากเลื่อนแผนไปเริ่มคนละช่วง (ปัดเป็นวันจันทร์ให้เอง และเลื่อนวันแข่งตาม) คนที่มีแผนอยู่แล้วจะถูกแทนที่ทั้งแผนและล้างประวัติติ๊ก
- **เฉพาะสัปดาห์ที่เลือก**: คัดลอกแค่สัปดาห์นั้นไปแทนที่สัปดาห์เดียวกัน (หรือใส่วันที่ปลายทางเพื่อลงสัปดาห์อื่น) สัปดาห์อื่นของเขาไม่เปลี่ยน
- แต่ละคนได้สำเนาของตัวเอง แก้แยกกันได้ต่อ ติ๊กทำแล้วแยกกัน
- ส่งเสร็จจะส่งอีเมลแจ้งต่อได้ด้วยปุ่ม "ส่งอีเมลให้ …" (ต้องตั้ง RESEND_API_KEY)

## Export / Backup
- **ทั้งระบบ** (แท็บ "นักกีฬา" → "สำรอง / กู้คืนข้อมูลทั้งระบบ"): ดาวน์โหลดนักกีฬา แผน และประวัติติ๊กทั้งหมดเป็นไฟล์ `k4rc-backup-วันที่.json`
  - ติ๊ก "รวมรหัสผ่านแบบเข้ารหัส" ถ้าอยากให้กู้คืนแล้วล็อกอินได้ทันที (ไฟล์นี้อ่อนไหว เก็บให้ปลอดภัย) หรือเอาออกถ้าจะส่งต่อให้คนอื่น
  - "กู้คืนจากไฟล์ backup": เพิ่ม/อัปเดตตามรหัสนักกีฬาในไฟล์ ไม่ลบคนที่ไม่อยู่ในไฟล์
- **รายคน** (แท็บ "แผนซ้อม" → "ดาวน์โหลดแผนนี้"): ได้ไฟล์ .json นำเข้าให้คนอื่นด้วยปุ่ม "นำเข้าไฟล์แผน" ได้
- **นักกีฬา** กดปุ่ม "สำรองแผน" ในเมนูเพื่อเก็บแผนและประวัติของตัวเองไว้เป็นไฟล์

## เพซของนักกีฬา (Recovery, LT1 (Easy), LT2 (Threshold), Marathon, 5K Pace, VO2Max, R Pace)
- **โค้ชกรอก:** หน้าโค้ช → แท็บ "นักกีฬา" → ในแถวของแต่ละคนกด "เพซของ …" → กรอกช่องเพซ (พิมพ์เช่น `5:30` หรือ `5:15-5:45` หน่วยนาที/กม. ระบบต่อท้าย "/กม." ให้เอง) → "บันทึกเพซ" เว้นว่างทุกช่องแล้วบันทึก = ลบเพซของคนนั้น
- **นักกีฬาดู:** เปิดเมนู (ปุ่ม "เมนู" บนมือถือ) → ปุ่ม "เพซของฉัน" เห็นเพซของตัวเองพร้อมวันที่โค้ชอัปเดต
- เพซผูกกับตัวนักกีฬา ไม่ผูกกับแผน จึงไม่หายเมื่อนำเข้าแผนใหม่ และ "ส่งแผนให้นักกีฬาคนอื่น" ไม่คัดลอกเพซไปด้วย
- รวมอยู่ใน backup ทั้งระบบ และเปิดดูได้ตอนออฟไลน์ (ค่าล่าสุดที่โหลดไว้)

## Environment variables (Netlify → Site configuration → Environment variables)
- `ADMIN_PASSWORD` รหัสผ่านโค้ช (จำเป็น ใช้เซ็นเซสชันนักกีฬาด้วย)
- `SESSION_SECRET` ไม่บังคับ ข้อความสุ่มยาวๆ ถ้าอยากแยกจากรหัสโค้ช
- `RESEND_API_KEY`, `EMAIL_FROM` ไม่บังคับ ใช้ส่งอีเมลสรุปตารางรายสัปดาห์
- `SITE_URL` ไม่บังคับ ที่อยู่เว็บ ใช้ทำปุ่ม "เปิดแอป" ในอีเมล

- **หน้าแรก = ฟีดทีม**: เมื่อนักกีฬากด "ทำเสร็จแล้ว" และใส่ RPE ผลซ้อมจะขึ้นเป็นโพสต์ให้ทุกคนในทีมเห็น (ชื่อ รูป ระยะ เวลา เพซ RPE ความรู้สึก) และหายเองเมื่อครบ 24 ชม. นับจากตอนบันทึก (แก้ทีหลังไม่ต่ออายุ ยกเลิกการติ๊กหรือลบ RPE = โพสต์หาย) อาการเจ็บและบันทึกถึงโค้ชไม่แสดงในฟีด
- แถบสัปดาห์ด้านบน (วงกลมติ๊กวันที่ทำแล้ว + จำนวนสัปดาห์ติดต่อกัน) มาแทนกล่อง "สัปดาห์นี้" เดิมในหน้าแรก
- นักกีฬาปิดการแสดงในฟีดได้ที่ โปรไฟล์ → แก้ไขโปรไฟล์ → "แสดงผลซ้อมของฉันในฟีดทีม"
- รูปโปรไฟล์ซิงก์ขึ้นเซิร์ฟเวอร์ (ย่อ 144px) เพื่อให้เพื่อนเห็นในฟีด
- **โปรไฟล์**: หัวโปรไฟล์ + 4 แท็บ ความก้าวหน้า (กราฟ 12 สัปดาห์ แตะเลือกสัปดาห์ได้, ความต่อเนื่องเดือนนี้) / กิจกรรม / ข้อมูล (เหรียญ เป้าหมาย ร่างกายเดิม) / เพิ่มเติม
- API ใหม่: `GET /api/feed`, `POST /api/avatar`; ที่เก็บ Netlify Blobs: `feed`, `avatar:<id>`

## ปรับหน้าตา (รอบล่าสุด)
- หน้าแรกไม่มีการ์ดงานแข่งแล้ว ไอคอนไฟ (ความต่อเนื่อง) ทั้งหมดเปลี่ยนเป็นรูปคนวิ่ง (`RUNNER` ใน index.html)
- ทุกหน้าใช้พื้นดำล้วน + การ์ดทึบ (บล็อกท้ายไฟล์ athlete.css) แท็บบาร์ล่างยังเป็นกระจกเหมือนเดิม
- โปรไฟล์: เอาตัวกรอง ทุกกีฬา/วิ่ง ออก (นับทุกกีฬารวมกัน กราฟแสดงระยะ กม.) และรวมแท็บ ข้อมูล + เพิ่มเติม เป็น "ข้อมูล"

## Supabase storage backend (K4RC deployment)

This version supports `K4RC_DATA_BACKEND=supabase` and stores app records in the existing `public.app_kv` table (`key` text primary key, `value` jsonb, `updated_at` timestamp). Configure `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` as Netlify environment variables only; never place the service-role key in browser code or commit it to Git. The app uses Supabase REST upserts and reads through Netlify Functions. If `K4RC_DATA_BACKEND` is not set to `supabase`, the legacy Netlify Blobs adapter remains available for local/legacy deployments. Do not run any migration or delete the old Blobs store as part of deploying this version.


## ดึงข้อมูลจากลิงก์ COROS และแชร์เวิร์คเอาต์
- หน้า "ทำเสร็จแล้ว" และหน้า "แชร์เวิร์คเอาต์" มีกล่อง "ดึงข้อมูลจาก COROS" วางลิงก์แชร์ (s.coros.com / sharepage.coros.com) แล้วได้ ระยะ เวลา HR เฉลี่ย และเส้นทาง (เซิร์ฟเวอร์ดึงรูปแผนที่ og:image ของหน้าแชร์ เฉพาะโดเมน *.coros.com แล้วฝั่งแอปแยกเฉพาะ "เส้น" สีเหลืองเขียวออกจากแผนที่ `routeFromMap` เก็บเป็นหน้ากากเส้นเล็ก ๆ ไม่เก็บแผนที่)
- HR เก็บเป็นค่าเฉลี่ยตัวเลขเดียว (ฟิลด์ `hr` ในผลซ้อม) ส่วนรูปเส้นทางเก็บในเครื่องนักกีฬาเท่านั้น (localStorage `rp_trk:<ชื่อ>`) เพราะบอกที่อยู่
- หน้าแชร์มีปุ่ม "เส้นทาง" และ "HR" เหมือนปุ่มอื่น (ขึ้นเมื่อมีข้อมูล) ตัวเลขบนภาพแชร์ย่อลงจากเดิม เส้นทางวาดเป็นเส้นเรืองแสงล้วน (ไม่มีแผนที่) ขนาดเล็ก อยู่ซ้ายมือเหนือค่าระยะทาง ข้างกันเป็นป้าย HR เล็ก ๆ (ทุกสัดส่วนและทุกแบบการ์ด)
- เวลาจริงในหน้า RPE เป็น นาที:วินาที และเซิร์ฟเวอร์เก็บเศษวินาที
- แถบเมนูล่างแบบ iOS 26 (เลนส์แก้ว) ดู `initTabbar` ใน index.html และบล็อก "แถบเมนูล่าง" ใน athlete.css

## อัปเดตล่าสุด
- เส้นทาง: แยกสีแบบนุ่ม (ไม่ตัดขอบแข็ง) ไม่ต่อเส้นเอง ปรับความหนาที่ความละเอียดต้นฉบับกันเส้นขาด ขนาดจุดเริ่ม/จบตามที่เห็นในแผนที่
- ตำแหน่ง: แบบแถว = ซ้ายเหนือตัวเลข (HR ใต้เส้นทาง), ตัวเลขใหญ่ = ใต้ระยะทางกลางภาพ, การ์ดกระจก = กลางภาพเหนือการ์ด
- แถบเมนูล่างเล็กลง (สูง 54 กว้างไม่เกิน 328) เลนส์นุ่มลง ไม่มีขอบรุ้งแรง/เด้ง ตอนลากเลนส์ตามนิ้วแบบหน่วงนิด ๆ เปลี่ยนหน้ามีเลื่อนเข้า/จางเข้า .3 วินาที
- แถบเมนูล่างขยายขึ้นจากรอบก่อน (สูง 62 กว้าง 88% ไม่เกิน 362 ไอคอน 24) และจังหวะแตะตามวิดีโอ: แถบขยายนิด เลนส์โผล่ ไหลไปแท็บใหม่ใน ~0.27 วินาที แล้วหดเป็นแท่งเข้ม
- แก้บั๊ก: หน้าโค้ชแสดงเวลาจริงเป็นทศนิยม (เช่น 39.15) ตอนนี้แสดง นาที:วินาที และแสดง HR เฉลี่ย / ฟีดทีมอ่านรูปโปรไฟล์พร้อมกัน (เร็วขึ้นเมื่อทีมใหญ่) / เพิ่มเลขเวอร์ชัน service worker

## เก็บกวาดและเสถียรภาพ (รอบนี้)
- เอาออก: โค้ดที่ไม่ได้ใช้ (หน้าต่างงานแข่งและตัวนับถอยหลังที่วิ่งทุกวินาที, `shLink`, ค่าคงที่ที่ไม่มีใครเรียก, สไตล์ที่เกี่ยวข้อง), การ์ดความต่อเนื่องที่ซ้ำในแท็บข้อมูล, ปุ่ม "ข้อมูลของฉัน" ที่ซ้ำกับ "แก้ไขโปรไฟล์", หน้าโค้ชในแคชของนักกีฬา
- หน้า "ซ้อมเป็นอย่างไรบ้าง": เห็นเฉพาะ ความเหนื่อย / ความรู้สึก / อาการเจ็บ ส่วน COROS, ระยะ-เวลาจริง, โน้ต พับไว้ใน "รายละเอียดเพิ่มเติม" และหลังบันทึกมีปุ่มแชร์เวิร์คเอาต์

- เสถียรขึ้น: Supabase หมดเวลา 8 วินาที + ลองซ้ำ 1 ครั้ง, ฐานข้อมูลล่มตอบ 503 พร้อมข้อความที่อ่านรู้เรื่อง, กด "ทำเสร็จแล้ว" ตอนไม่มีเน็ต/ระบบล่ม เก็บคิวในเครื่องแล้วส่งให้เองเมื่อกลับมา
- แก้บั๊ก: ประวัติกิจกรรมของนักกีฬาแสดงเวลาเป็นทศนิยม (เช่น 39.15) ตอนนี้เป็น นาที:วินาที
- ทดสอบ: `npm test` (API 14 ข้อ) และ `python test/ui_smoke.py` (หน้าจอ 15 ข้อ) รันบน GitHub Actions ทั้งสองงาน

## สลับฐานข้อมูลระหว่าง Supabase กับ Netlify Blobs
โค้ดรองรับทั้งสองแบบอยู่แล้ว เลือกด้วยตัวแปร `K4RC_DATA_BACKEND` (ไม่ต้องแก้โค้ด):
- `supabase` = เก็บใน Supabase (ตาราง `app_kv`)  ·  ลบตัวแปรนี้ หรือใส่ `blobs` = เก็บใน Netlify Blobs
ทั้งสองที่เป็นที่เก็บแยกกัน ข้อมูลไม่ซิงก์กันเอง ขั้นตอนย้ายข้อมูล:
1. หน้าโค้ช → สำรองข้อมูล (ติ๊ก "รวมข้อมูลล็อกอิน") ดาวน์โหลดไฟล์เก็บไว้
2. Netlify → Site configuration → Environment variables แก้/ลบ `K4RC_DATA_BACKEND` แล้ว deploy ใหม่
3. หน้าโค้ช → กู้คืนจากไฟล์สำรอง จากนั้นเช็กว่านักกีฬา แผน และผลที่ทำแล้วอยู่ครบ
ข้อมูลเดิมในที่เก็บเก่ายังอยู่ ไม่ถูกลบ สลับกลับได้ รูปโปรไฟล์และโพสต์ฟีด 24 ชม. ไม่อยู่ในไฟล์สำรอง: รูปจะถูกส่งขึ้นใหม่เองเมื่อนักกีฬาเปิดแอป (ถ้ายังมีรูปในเครื่อง) ส่วนโพสต์ฟีดจะเริ่มใหม่
